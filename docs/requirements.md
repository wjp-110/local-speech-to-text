# 需求理解与功能拆分

## 1. 项目目标

实现一个 B/S 架构的本地语音识别系统：浏览器采集麦克风音频或上传音频文件，由部署在本机的开源 ASR 模型完成中文/英文识别，并在页面展示结果、音频时长与处理耗时。

## 2. 功能需求

| 编号 | 功能 | 是否必做 | 实现说明 |
| --- | --- | --- | --- |
| F1 | 浏览器麦克风录音 | 必做 | MediaRecorder，最长 60 秒，状态/计时提示，失败提示 |
| F2 | 音频文件上传 | 必做 | 至少 WAV，兼容浏览器录音 WebM/OGG，共用识别接口 |
| F3 | 本地中英文识别 | 必做 | faster-whisper，语言参数 `zh` / `en`，CPU int8 |
| F4 | 结果展示 | 必做 | 语言、状态、文本、音频时长、处理耗时、复制 |
| F5 | 异常处理 | 必做 | 权限、空文件、损坏文件、超限、模型失败等 |
| F6 | 实时识别 | 加分（已实现） | 录音时每 4 秒提交已积累音频快照，页面持续更新实时预览 |

## 3. 非功能需求

- 架构：Browser / Server
- 后端：Python 3.12 + FastAPI
- 前端：原生 HTML / CSS / JavaScript
- 推理：本地开源模型，CPU 必须支持
- 离线：模型准备完成后识别过程不访问互联网
- 测试：pytest，区分 Mock 测试与真实模型测试
- 启动方式：`uvicorn app.main:app --host 127.0.0.1 --port 8000`

## 4. 关键假设

1. 用户使用最新版 Chrome/Edge，通过 `http://127.0.0.1:8000` 访问，浏览器允许 localhost 使用麦克风。
2. 首次安装时可联网下载模型权重；之后可断网运行。
3. 普通开发电脑 CPU 可以承受默认 `small` 模型的 int8 推理；低端机器可切换到 `base`。
4. 系统不需要用户登录、数据库、历史记录、翻译或说话人识别。

## 5. 边界条件

- 单次录音 ≤ 60 秒，到时自动停止。
- 单文件 ≤ 10 MB。
- 支持语言参数仅 `zh` 和 `en`，非法值返回 4xx。
- 不支持的文件格式返回 415；无法解码的音频返回 400。
- 模型加载或推理失败返回 500，并给出可理解的错误信息。
- 音频中没有语音时返回空文本，不崩溃。

## 6. 验收映射

需求文档第 9 节的完成标准，对应本项目的验收点：

1. README 中启动命令可直接运行。
2. 浏览器可授权、录音、停止。
3. 录音文件通过 multipart 提交到 `/api/transcribe`。
4. 真实本地模型分别识别中英文样本。
5. 结果正确返回并展示，可复制。
6. 上传 WAV / WebM 文件可独立验证。
7. 常见错误有提示而不崩溃。
8. `python -m pytest -q` 通过，且提供真实模型测试命令。
9. 源码、README、设计/测试文档、AI 开发记录齐全。
